No credentials in this server's environment. Every upload will be refused. Stop the web server and start it with them exported: export ES_USER ES_PASSWORD && python3 web/app.py

Latency. A burst cannot be seen until the DMA period holding it fills: 4 MiB is about 2.1 s at 2 MSa/s, and that is usually most of the wait. Setting DMA buffer to 262144 brings it to about 130 ms. The large default exists because an SD card stalls for seconds while a continuous capture writes to it — monitor mode writes almost nothing, so a smaller period is much safer here, but watch for DMA ring overflow in the output and raise it again if you see one.

Bursts are decoded and uploaded by sr2es.py in a separate process, one at a time, so nothing slow ever runs in the capture path. A burst that closes while a shipper is busy waits on disk for the next sweep, and a failed upload is retried rather than lost. Once the cluster confirms a burst, its .sr is deleted — except under Raw, where the document carries no payload and the file is the only copy. Credentials are never sent from this page: pi5la reads ES_API_KEY, or ES_USER and ES_PASSWORD, from the environment it inherits.

Runs until you press Stop unless you set a limit.
